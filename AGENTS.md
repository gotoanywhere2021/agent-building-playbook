# AGENTS.md — Operational Cycle

This repo is a curated collection of patterns. One canonical source feeds two
generated views. **Edit only the source; never hand-edit generated files.**

## Source of truth

- `patterns/*.md` — the curated pattern files. Flat frontmatter
  (`title`, `one_liner`, `dimensions`) + a markdown "pearl" body. The filename
  (`{kebab-title}.md`) is the identifier. Patterns arrive via GitHub PRs.
  See `SUBMISSIONS.md` for the authoring contract; `.wiki/context/schema.md`
  for the machine schema.

## Generated views (do not hand-edit)

| View | File(s) | Generator | Audience |
|---|---|---|---|
| Agent index | `INDEX.md` | `scripts/build-index.sh` | agents (dense, token-efficient) |
| Human wiki | `wiki/` (static HTML, zh-CN) | `.wiki/scripts/publish.sh` | humans (Palantir-docs-style: topbar search, sidebar family › dimension tree, breadcrumbs) |

The wiki's navigation tree comes from `wheel/taxonomy.yaml` (generated by
`scripts/build-wheel.py`); `publish.sh` validates it against `patterns/` and
fails loud on drift — regenerate the taxonomy before publishing when patterns
change. UI is Chinese with English keyword annotations; translations live in
the human-curated copy layer `.wiki/context/zh.json` (titles/one-liners),
`.wiki/context/zh-bodies/{slug}.md` (translated bodies, English original shown
collapsible), and `.wiki/context/diagrams/{slug}.mmd` (one Mermaid flowchart
per pattern, rendered by the vendored loader copied from `.wiki/assets/`) —
missing entries fall back to English / no diagram, so update the layers when
adding/renaming patterns. The sunburst "wheel" browser is retired from the
human site — `wiki/explore.html` is now the pattern-catalog browser. Decision
records: `docs/plans/2026-10-24-palantir-wiki-redesign.md`,
`docs/plans/2026-10-24-zh-body-translation.md` and
`docs/plans/2026-10-24-pattern-diagrams.md`.

## Cycle

1. **Add / edit a pattern** in `patterns/` (PR flow).
2. **Rebuild the agent index:** `bash scripts/build-index.sh` → `INDEX.md`
   (a GitHub Action also runs this on merge to `main`).
3. **Render the human wiki:** `bash scripts/build-index.sh`'s human counterpart,
   `/wiki-publish` (→ `.wiki/scripts/publish.sh`) → `wiki/`.

`INDEX.md` and `wiki/` are two renderings of the SAME `patterns/` source — they
never diverge from it, and neither is edited by hand.

## Wiki commands

- `/wiki-publish` — render `patterns/*.md` into `wiki/` (and package a zip under
  `.wiki/dist/`). Portable: bash + python3 stdlib only.
