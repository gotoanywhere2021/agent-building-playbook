# Shared-Loop Swarm Board v2 — Exemplar 链接健康检查

任务：检查 patterns/ 全部 132 个模式 Exemplars 小节里的 378 个 URL 的可达性。

## PROTOCOL v2 — 每个工人执行完全相同的循环（无主管，看板是唯一协调面）
1. READ 本看板，找第一条 `STATUS: UNCLAIMED` 的批次。
2. CLAIM：`mkdir swarm-run/claims/<批次ID>`（原子锁；已存在=输了竞争，回 1）。 成功后把该批次行改为 `STATUS: CLAIMED BY <你> | STARTED <UTC>`（只准改这一行）。
3. WORK：对批次内每个文件，grep Exemplars 小节的 URL，逐个 `curl -s -o /dev/null -w "%{http_code}" -L --max-time 20 -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64)" "<url>"`。 同一域名连续 3 次非 2xx/3xx → 该域名其余 URL 记 RATE_LIMITED_SKIP。
4. RECORD：向自己的 `swarm-run/results-<你>.md` **追加**（append-only）： 每个文件一行 `FILE patterns/x.md | urls=N ok=K bad=L skip=S`，其下每 URL 一行 `CODE | url`。
5. CLOSE：在结果文件追加 `BATCH <ID> DONE files=N urls=M ok=K bad=L skip=S`， 再把看板该批次行改为 `STATUS: DONE | WORKER <你> | UPDATED <UTC>`。
6. 回 1。所有批次 DONE → 结果文件末尾写 `WORKER <你> STOPPED <UTC>`，结束。

完整性规则：只写自己的 results 文件 + 自己的认领目录 + 自己批次的看板行；禁止改动仓库其他文件。

## 观察入口（任何人可运行，只读派生视图）
`python swarm-run/dashboard.py` → 渲染 `swarm-run/dashboard.md`（进度/工人/批次/坏链汇总）
