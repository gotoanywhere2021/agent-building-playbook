# 共享循环群体（ZCode 实现）— 运行档案

模式：`patterns/shared-loop-not-supervisor.md` · 运行日期：2026-10-25 ·
宿主：ZCode（Windows，Git Bash）

## 任务

校验 `patterns/` 全部 132 个模式 Exemplars 小节的 **378 个 URL** 可达性。
切成 5 个同质批次（交错切分），**无中央分配**：两个子智能体工人（W1、W2）
只依据共享看板自行认领。

## 涌现行为（本次实测记录）

- **竞争与让出**：W1 曾竞争 B00 失败（mkdir 原子锁），按协议换批，最终
  W2 拿到 B00。
- **自纠错**：W1 发现自己首批结果文件存在"占位+汇总"双 FILE 行格式缺陷，
  任务中途自行停止、修正格式、重建已产数据（校验和自洽），继续循环。
- **停止条件生效**：两工人在"全部批次非 UNCLAIMED 且自分批次 DONE"时
  各自写 STOPPED 行退出，无遗留、无死循环。

## 链接健康结论（三轮验证）

1. 群体轮：162 个 URL 实例拿到确证 ok；66 个唯一 URL 未决。
2. 换条件复验（本地 curl，重试 ×2）：42/66 恢复 200。
3. 连接级失败重试：再恢复 12。

**最终：0 个确认死链（全程无 404）；12 个本机不可验证**——
6 条 wikipedia（本地网络不可达）、archive.org/medium/cs.virginia
（连接重置）、dl.acm.org（反爬 403）、lesswrong（429 限频），均为
全球可访问的规范 URL。未修改任何模式文件。

## 教训

- **这是协调模式，不是效率模式**：两个子智能体合计 ≈34M 子代理 token
  完成 378 次 curl 检查；同样的机械工作用一个本地脚本几分钟即可。
  群体的价值在"需要模型判断的分布式工作"，机械批量请走脚本
  （呼应 `start-least-agentic`）。
- **网络条件是环境的一部分**：W1 运行窗口内主机网络恶化（60 超时、
  6 域名触发限流保护封锁），导致其 bad/skip 数据大量虚高——判定
  "死链"前必须换条件复验（呼应 `real-environment-execution`、
  `safety-guarantees-dont-transfer`）。
- **ZCode 宿主约束**：子智能体并发上限实测为 2（5 连发并发会被
  concurrency limit 拒绝）；群体规模按宿主上限设计即可，看板协议
  对工人数量不敏感。
