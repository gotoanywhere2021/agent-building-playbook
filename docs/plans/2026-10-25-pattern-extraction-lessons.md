# Note — 内容提炼心得：从外部内容源到模式的六个教训

**日期：** 2026-10-25 · **类型：** 教训/心得（Agent Note） · **上篇：**
`docs/plans/2026-10-25-mindofuture-intel-summary.md`（其上篇：
`docs/plans/2026-10-24-mindofuture-sourcing-security-dimension.md`）。

## 问题

前两篇 Note 记录了结果（收了什么、漏斗说明什么），但提炼过程本身的
方法论没有沉淀。下次对任何外部内容源（播客、频道、书、论文集）做
模式提炼时，会重踩同样的坑：先写后查、凭标题立条、落选不留痕。

## 心得（六条）

1. **先读 INDEX，再读源——去重才是主要工作量。** 本次 51 条落选中
   ≈15 条是与既有模式直接重叠；识别这些重叠花的精力不少于撰写 12 条
   新模式。既有注册表既是地基也是过滤器：不通读 `INDEX.md` 就开始
   写，产出的会是复述而非增量。
2. **标题可初筛，立条必须一手证据。** 这个频道的标题自带论点
   （"沙箱并非可选"），标题级初筛把 1290 降到 63 是可行的；但 12 条
   收录每条都核对了简介或页面内容。证据不足的正确处置是进观察名单
   而不是先收再说——宁可 12 条都立得住，不要 20 条里 8 条存疑。
3. **实例 ≠ 规则，一期 = 0–1 个模式。** 演讲是叙事，模式是带
   When/When-NOT 的可复用决策规则。多数"好内容"其实是既有规则的新
   证据（exemplar），不是新规则——所以第二收获层（给既有模式补
   exemplar）是真实价值，本次只兑现了 1 条，backlog 还有 5 条。
4. **落选台账和收录清单同样有档案价值。** 51 条落选按
   重叠/边缘/域外/时效四类写了去向，观察名单把下次回挖成本从
   "通读 1290"降到"读 12 条 + 补简介"。拒绝的理由不落档，下次就会
   重新纠结一遍。
5. **亚线性是特性不是缺陷。** 提取量若随输入线性增长，说明在记话题
   而不是提炼规则。收敛率（1290 → 12，≈1%）本身是该领域决策空间
   实际宽度的一次测量——这个读数比多凑 8 个模式更有信息量。
6. **采集也是工程：为风控设计退路。** 全量列表接口被 -352/-412 拦，
   合集接口不设防；简介接口限流则以 8s 间隔重试 + 浏览器兜底 + 增量
   落盘。对外部源做可靠性设计时，这本手册自己的模式
   （fail-loud、persist-state、搜索替代遍历）就是检查清单——
   提炼者被自己的手册反哺，是个值得记下的回环。

## 决定

1. 本 Note 入库，与上两篇互链，构成完整链路：取数方法 → 情报结论
   与断点 → 提炼方法论。
2. 后续任何"外部内容源 → 模式"任务，按本清单顺序执行：
   读 INDEX → 标题初筛 → 简介佐证 → 重叠对照 → 立条/补 exemplar/
   观察名单三分 → 落选台账随 PR 归档。

## 考虑过的选项

- **并入上篇 Note** — 否：决策 Note append-only，且上篇是数据台账、
  本篇是方法论，混写会让两类读者都难检索。
- **写进 README / SUBMISSIONS.md** — 否：这是"怎么提炼"的个人教训，
  面向维护者而非贡献者，放贡献契约里是噪声。
- **只在 PR 评论里说说** — 否：评论随合并沉底，Note 才能被下次会话
  按 AGENTS.md 渐进披露路径找到。

## 后果

- 下次同类任务的冷启动成本从"重新发明流程"降为"执行清单"。
- 六条心得中第 1、4、5 条同时是本手册既有模式的再确认
  （`build-a-pattern-registry`、`register-the-unknowns`、
  `anchor-on-canonical-names` 的反面教训），手册与实践互相验证。
- 若未来出现第二个同类源（如另一档播客），本清单即是对照实验的
  控制变量：同流程、不同源，收敛率可直接对比。
