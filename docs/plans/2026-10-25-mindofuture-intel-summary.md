# Note — Mindofuture 情报汇总：1290 → 12 的漏斗、落选名单与观察项

**日期：** 2026-10-25 · **类型：** 情报汇总（Agent Note） · **上篇：**
`docs/plans/2026-10-24-mindofuture-sourcing-security-dimension.md`。

## 问题

上篇 Note 记录了取数路径与收录决定，但没有回答一个更根本的问题：
1290 个窗口内视频只产出 12 个模式（≈1%），这个收敛率说明了什么、
落选的 51 个短名单候选去了哪里、以及下一次回来挖这个源时该从哪里
继续。缺了这份汇总，下次会话会重复全量通读。

## 漏斗与读数

```
窗口 2026-01-24 → 2026-10-24（约 9 个月）
全频道视频        2123 unique（站方计数 2751，合集去重后 2123）
窗口内            1290
射程内（智能体构建）≈ 530–600   ← AI Engineer 合集 528 + AI 应用开发 2
                                   + 论文/讲座·访谈中 agent 相关期数
短名单            63（按主题聚类挑选）
收录              12（短名单的 19%）+ 1 条既有模式 exemplar 充实
落选              51
```

**收敛率的三个读数：**

1. **知识本身收敛**：主体是一档播客（AI Engineer，528 期）。标题级
   主题复现计数：沙箱 ≥5 期、harness 工程 ≥6 期、智能体记忆 ≥8 期、
   评估/评审 ≥12 期。1290 期 ≈ 同一批论点换嘉宾重演，不是 1290 个
   想法。模式抽取是亚线性蒸馏——若能线性提出 200 个模式，产出的
   是话题清单而非决策手册。
2. **注册表在成熟**：最强的一些期数（Prove It's Done、LLM 知识库
   实用指南、记忆架构详解）落在既有 118 个模式的射程内，正确处置
   是补 exemplar 而非新建条目。边际产出递减是注册表逼近领域决策
   空间全集的证据，不是源材料没价值。
3. **12 是保守下界**：筛选口径偏严（要求与现有模式不重叠 + 论点
   有一手出处）。放宽口径、补足简介考证，20+ 可达。

## 落选的 51 条去向（短名单分类账）

**A. 与既有模式直接重叠（≈15 条，弃收正确）**

| 落选期数 | 既有模式 |
|---|---|
| 百工具智能体实为陷阱 | `code-execution-tools`（单一代码执行工具替代几十个工具定义） |
| 智能代理需要特性标志 | `separate-merge-from-exposure`（特性标志正是该模式主体） |
| 停止提示词工程（Sentry） | `context-over-prompt` |
| 日志即为代理体 | `emit-events` / `make-runs-replayable` |
| 偏好胜过基准（模型路由） | `role-based-routing` / `match-model-to-stage` |
| 微调模型是技术债 | `lexical-first-retrieval`（"停止用微调修检索"臂） |
| 教会智能体证明任务已完成 | `self-verification`（已补 exemplar） |
| 代码审查的消亡 / 如何终结代码审查 | 审查类既有条目覆盖其半，数据结论待考 |

**B. 边缘候选——观察名单（≈12 条，下次优先回挖）**

- **Context Layer 簇**（什么是上下文层 / 从记录系统到上下文系统 /
  面向智能体的数据上下文层 / 2026 上下文工程，共 ≥4 期）：描述的是
  同一基础设施趋势；等独立证据再积累 1–2 期可立模式，暂被既有
  context-engineering 条目部分吸收。
- 你的智能体需要一个保存按钮（显式状态持久化，与 checkpoint 系
  最近但不同）；你的护城河是数据模型；ReviewDebt 评分框架；
  速度病（全队提速十倍的组织后果）；500 人共感编程 30 天；
  理解成为新的瓶颈；被拴住的智能体就是我们自身。
- 共同缺口：只有标题级证据，简介被限流未取全——回挖前先补简介。

**C. 主题域外（≈20 条）**：数学/物理/法律/职场/商科等合集中的
agent 弱相关期数。

**D. 时效性内容（≈4 条）**：模型发布、基准动态——不满足模式
"耐久"门槛。

## 决定

1. 本 Note 作为该源的**断点续挖文件**：下次从观察名单 B 类出发，
   先补简介（`web-interface/view` 限流约 8s/次可绕），再评估立条。
2. **Exemplar 补强 backlog**（不必等新模式）：`demand-independent-proof`
   ← 验证器才是王道；`eval-driven-development` ← 构建真正重要的评估；
   `make-runs-replayable` ← 日志即代理体；`supervise-many-agents` ←
   鼠标力（无法衡量即无法管理）；`attention-is-the-scarce-resource` ←
   理解成为新的瓶颈。
3. 情报结论回灌手册自身：`build-a-pattern-registry` 模式（"团队会
   反复重新发现同一批 loop"）在这个频道上获得一次大规模实证——
   一百余位讲者两年内收敛到同一批论点。1290 → 12 是领域决策空间
   实际宽度的一次实测。

## 考虑过的选项

- **并入上篇 Note** — 否：决策 Note append-only，且上篇记录"怎么取、
  收了什么"，本篇记录"漏斗说明什么、剩下什么"，职责不同。
- **放宽口径一次收 20+** — 否：重叠条目会稀释既有维度的语义
  （security 收录时已做过这类取舍）；观察名单等证据补齐再收。
- **只写 PR 描述不留档** — 否：PR 描述随合并沉底，Note 才能被
  下次会话按 AGENTS.md 渐进披露路径找到。
