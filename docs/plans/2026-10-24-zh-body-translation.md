# Note — 模式正文全量中文化（第一轮）

**日期：** 2026-10-24 · **类型：** 决策（Agent Note） · **上篇：**
`docs/plans/2026-10-24-palantir-wiki-redesign.md`（该篇把"正文也全量翻译"
列为暂缓项，本篇接续执行，不改写它）。

## 问题

第一轮改版后，详情页只剩正文（pearl body）是英文——用户在浏览详情页时
语言断裂最明显。"暂缓"的理由（113 篇 × 质量要求 ≈ 大工程）依然成立，
但可以分两半解：**译文落盘为独立文件层 + 英文原文折叠保留**，让翻译
可以批量进行、逐篇校对、随时回退，而 canonical 英文源（`patterns/`）
一个字不动。

## 决定

1. **译文层 = `.wiki/context/zh-bodies/{slug}.md`**：一个模式一个文件，
   内容为译文正文（无 frontmatter）。`publish.sh` 加载后作为主正文渲染；
   文件不存在则回退英文正文（与 zh.json 的回退语义一致）。
2. **英文原文不丢弃**：有译文时，页面在中文正文下方渲染
   `<details class="original">英文原文（Original English）</details>`
   （默认折叠）。中英两份正文共享锚点命名空间（`what-it-is` 与
   `what-it-is-2`），右栏"本页内容"取自中文正文。
3. **正文自带 `## Related` 时抑制生成器计算的相关区块**（作者策展优先）。
4. **渲染器补齐管道表格支持**（正文里确有表格：如 long-horizon-memory
   的记忆层次表、match-model-to-stage 的角色表）。
5. **第一轮译文由 AI 批量翻译**（6 个子代理各负责约 19 篇，规则统一：
   标题双语式 `## 这是什么（What it is）`、术语首现括注英文、
   `patterns/xxx.md` 行内代码逐字保留以保住站内链接、URL 不动、『』引号）。
   译文属**待人工校对**状态；逐篇校对后即成为 zh-bodies 的人工策展层。

## 考虑过的选项

- **译文写进 zh.json 的 body 字段** — 否：113 篇正文塞一个 JSON 会把它
  变成不可维护的巨石；一模式一文件才能逐篇评审与 diff。
- **直接改写 patterns/*.md 为中文** — 否：破坏 canonical 英文源与
  INDEX.md/agent 视图，且 GitHub 上游 PR 流程以英文为准。
- **机器翻译不入库、渲染时实时调用** — 否：不可复现、不可校对，且静态站
  不应依赖外部服务。

## 后果

- 正向：113/113 详情页中文正文 + 英文原文可查；翻译质量可逐篇迭代
  （改一个 md 文件重发布即可）；站内链接与外链在译文中保持可用。
- 代价：新增/改名模式时需同步维护 zh.json（标题/摘要）与
  zh-bodies/{slug}.md（正文，可暂缺）；两份译文层合计约 0.5MB，全站
  体积可接受。
- 校验：`tests/test_wiki_publish.sh` 扩展锁定——中文正文渲染、原文折叠、
  中英锚点去重、无译文时不出现折叠块。
- 遗留：译文待人工校对（文件头部无需标记；校对即编辑该文件）。
