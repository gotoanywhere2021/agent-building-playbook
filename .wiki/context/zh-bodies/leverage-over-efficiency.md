## 这是什么（What it is）

关于 agent 的用途存在两个战略框架，选择哪个会塑造此后的一切。效率（efficiency）框架问的是：如何用更少的人做同样的工作？杠杆（leverage）框架问的是：同样的人如何构建更多、探索更多、现代化更多、在更大规模上运转？对任何试图增长、竞争或转型的组织，杠杆框架更有用，而且它更准确地描述了先进实践者已经在做的事情。他们不是在做一比一的任务替换；他们正在创造此前不存在的新运营面（operating surfaces）——管理其他 agent 的 agent、专门为 agent 使用而构建的工具、通宵运行的工作流、从会议转录（transcript）中挖掘知识的系统、语义迁移（semantic-porting）流水线、对抗式评审小队、生产反馈回路。这些没有一样是『同样的工作，更便宜』。它们是此前在人力规模下不可能完成的新工作。其反直觉的推论是：人的角色变得更重要，而不是更不重要——当 agent 吸收了执行工作，每一次人类判断的波及半径（blast radius）都在扩大，因此驾驭这套系统的人的素质，比他们亲手敲实现时更加重要。

## 适用场景（When to reach for it）

- 制定 AI 战略时：在『用更少的人做同样的事』与『同样的人做远多于从前的事』之间做刻意选择，并留意你的路线图和指标悄悄预设了哪个框架。
- 当实践者的个人吞吐量已经饱和，下一步增益来自构建能在其睡觉时运转的工具、agent 和工作流。
- 决定投资方向时：优先构建新的运营面（为 agent 造 agent、通宵流水线、评审小队），而不是从既有任务上抠边际成本。
- 论证编制或评判『AI 成熟度』时，把问题从省下的成本重构为解锁的规模、范围与雄心。
- 当资深人员是瓶颈时：让他们的判断跨越许多工作流发挥作用，而不是要求他们更快地完成同样数量的工作。

## 慎用场景（When NOT to）

- 效率框架并非总是错的——在收缩、成本受限或利润率商品化的情境下，用更少资源做同样的工作可能恰是正确目标。
- 不要把『杠杆』用作掩盖真实成本或质量问题的委婉说法；如果规模化之后的产出更糟，更多的规模不是杠杆。
- 杠杆会乘以驱动它的任何判断；不要去规模化一个底层决策或品味尚不可靠的工作流。
- 这不是无节制启动 agent 活动的许可证；新的运营面仍然需要注意力预算、护栏（guardrail）和证据。

## 实例（Exemplars）

- Andy Grove, *High Output Management* (1983) — https://www.shortform.com/blog/andrew-grove-high-output-management/ — 经典先例（链接是 Shortform 的摘要；该书没有稳定的出版社页面）：管理杠杆公式（管理者产出 = Σ 活动 × 杠杆）确立了杠杆——而非速度或人数——是产出的驱动因素，AI 即杠杆的框架直接延伸了这一思想。
